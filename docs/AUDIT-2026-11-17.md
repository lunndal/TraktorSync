# Audit 2026-11-17 (ponytail-audit)

Scope: whole repo (`Sync-TraktorLibrary.ps1`, README, docs, .github). Nothing was run: no `.nml` or library was available to test against. Assumed load: one person running it by hand on a library of a few thousand tracks.

Status of each item: all open.

## What this repo does

`Sync-TraktorLibrary.ps1` is a single 599-line PowerShell script. It scans `Music\Library\Tracks`, compares it with Traktor's `collection.nml`, and adds new tracks and M3U playlists to a copy of that file. With `-Apply -InstallToTraktor` it backs up the live file and replaces it.

## Must fix

### 1. A track that can't be read gets silently deleted from a Traktor playlist
`Sync-TraktorLibrary.ps1:L156-168`, `L321-337`, `L351`

- **What this is:** M3U files are the source of truth. Any track in the Traktor playlist but not in the M3U is treated as "removed" and dropped when the merge is written.
- **Problem:** `Read-M3U` reads every file as UTF-8. Classic `.m3u` files are often ANSI, so a track like `Björk` becomes a "file not found" warning and is skipped. The skipped track then counts as removed. The same happens if the drive holding that track is unplugged. The only sign is one yellow `!` line, and `-Apply` writes the change with no question.
- **Fix:** Don't treat a skipped track as removed. Keep any Traktor track whose M3U line was skipped, for example by putting those paths into `$wantKeys`. Or stop if any playlist has warnings, unless something like `-AllowSkipped` is passed.
- **If we skip it:** A playlist loses tracks after a normal sync. You only notice mid-set.

## Should fix

### 2. `-RemoveMissingTracks` can wipe cues if the library is unavailable
`L279`, `L491-495`

- **What this is:** The switch deletes collection entries whose file is gone.
- **Problem:** If `Library\Tracks` exists but is empty or half-synced (unplugged disk, cloud folder not downloaded), every entry under Library counts as missing and is deleted, with its cues, grids and ratings. A renamed file does the same: the old entry is deleted and a new blank one is added.
- **Fix:** Stop if more than about 10% of the entries would be removed, unless `-Force` is given. Mention the rename case in the README.
- **If we skip it:** One bad run with the switch on throws away years of cue work. The backup saves you only if you notice.

### 3. "Existing entries are byte-for-byte untouched" is not checked
`L203-205`, `L537-547`, `L549-554`

- **What this is:** The script loads the XML, edits it, and writes the whole file back. The README promises old entries survive unchanged.
- **Problem:** The check after writing only counts entries. If the XML writer changes how a quote, an ampersand or a line break is escaped, nobody would see it. Not verified whether Traktor reads such changes the same way.
- **Fix:** Compare each original entry (`OuterXml`) with the merged one before the install step, and refuse to install on any difference. About four lines.
- **If we skip it:** Entries could be re-encoded in a way Traktor reads differently, with no warning.

### 4. No test for the risky logic
`L74-87`, `L90-137`, `L342-360`

- **What this is:** Path encoding, the FLAC tag reader, and the diff that decides added, removed and reordered tracks.
- **Problem:** `docs/TESTING.md` is an empty template, and the script runs everything on load, so nothing can be tested on its own. Edge case in the diff: if the Traktor side holds the same track twice, the two lists differ in length and "reordered" can be reported wrongly.
- **Fix:** Add a tiny sample set of a few files and run `-ReportOnly -WorkDir <temp>` against it. First check: `ConvertFrom-TraktorLocation (ConvertTo-TraktorLocation $p)` returns `$p` for a path with spaces and non-ASCII letters.
- **If we skip it:** A later change to the diff or path encoding can break output unnoticed.

### 5. The FLAC reader hides all errors
`L134`

- **What this is:** An empty `catch { }` around the whole tag read.
- **Problem:** A damaged tag block silently falls back to guessing the title from the file name, and nobody is told.
- **Fix:** In the catch, add `Write-Warning "Tags unreadable: $Path"`.
- **If we skip it:** Wrong artist and title in Traktor, with no clue why.

### 6. Every run copies the whole collection into `work/`, even `-ReportOnly`
`L200`

- **What this is:** A fresh `collection.original.<time>.nml` plus a report, every run.
- **Problem:** `.nml` files for a big library are tens of MB, so `work/` grows without limit.
- **Fix:** For `-ReportOnly`, load the live file directly. Or keep only the newest few copies.
- **If we skip it:** The disk slowly fills.

## Nice to have

7. Two M3U files with the same base name silently overwrite each other (`L317-336`): `x.m3u` and `x.m3u8`, or `A.m3u` and `a.m3u`. Warn on a duplicate name.
8. Hardcoded default `Traktor 4.5.1` (`L42-43`) breaks on the next Traktor version. It stops with "Not found", so it is safe. Pick the newest folder under `Traktor\Root` automatically.
9. README typo: `workllection.merged.nml` should be `collection.merged.nml`.
10. Placeholder files: `docs/` (8 files), `.github/prompts/` (4 files) and `.github/copilot-instructions.md` hold about 185 lines of template text. Delete what is not used. Contents not read beyond line counts.

## Verdict

The backup and install steps are careful: they check that the live file hasn't changed, verify the backup by hash, and refuse while Traktor is running. Fix item 1 first, then the guard from item 2, then the entry-equality check from item 3 (it backs the README's main promise).

Lean: -185 lines of placeholder docs possible, 0 dependencies.
